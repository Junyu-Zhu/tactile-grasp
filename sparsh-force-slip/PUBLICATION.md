# 源码公开与 Git 归档说明

## 本次整理的边界

保留训练、推理、评价、数据适配及必要检查的源码；排除原始数据、模型权重、
特征缓存、预测、训练日志、报告、运行状态、实验清单、pipeline 和交付副本。
排除通过 `.gitignore` 与 `git rm --cached` 完成，不删除磁盘上的实验材料。
`runbooks` 仅保留根目录 shell 入口，不保留各次运行生成的子目录。

`experiments` 使用源码白名单。当前只自动接纳 `.py` 和 `.sh`；需要公开的
配置应逐项审查并加入白名单，不应把所有 JSON 当成记录或一律公开。
目前配置/划分/授权等私有记录不在公开范围内，因此这是源码归档，不是已经
验证的第三方开箱复现版本。详细限制见 README。

## 不要直接推送整个本地 main

整理时，本地 main 有一个尚未推送的大型仿真提交，服务器 main 则是更旧版本。
force-slip 整理与该仿真提交应分开。不能把服务器旧 main 强推覆盖 GitHub，
也不能在未确认范围时把本地 main 的无关提交一起发布。

整理改动应发布到基于远端最新 main 的独立分支；原工作区、其他分支和旧历史保留。
分支推送、合并 main 和修改仓库可见性是分别处理的操作。
提交前应检查 `git diff --cached --stat` 和 `git diff --cached --name-status`。
不要使用 `git add .` 收集未知生成文件，也不要强制推送。

## .gitignore 不会清除历史

已提交的日志、报告和 pipeline，即使从最新提交停止跟踪，仍存在于历史中。
将原仓库直接改为 public 会暴露可访问的历史和其他分支；一次清理提交并不
等于已清理整个公开历史。当前基础仓库也包含仿真等其他研究代码。

本项目继续使用原 tactile-grasp 仓库，通过独立的源码整理分支保留审查边界。
在将仓库整体公开前，需要检查所有将被公开的历史和分支；若需要历史清理，
应先备份并明确重写范围，不能仅凭最新分支已排除记录就直接切换为 public。
本次源码整理不重写历史，也不宣称旧日志已经从历史中删除。

公开并不自动赋予第三方软件使用许可。发布前需确定自有代码许可证，并保留
上游代码的版权及许可要求；不能默认给全部研究代码和外部资源重新授权。

## 验证范围

本次检查包括当前源码语法、常见高置信凭据模式、忽略规则、索引文件类型和
停止跟踪后的磁盘 SHA256 保持不变。没有重新训练，没有宣称全历史无敏感信息，
也没有宣称所有历史脚本已经跨机器复现。

私有整理快照、恢复索引和具体主机差异保存在仓库被忽略的
`pipeline/git-publication-20261002/`，不作为公开材料。
