# 3 — 阶段3：风险校准与控制信号选择

## 前置条件

必须已有：

- `model_forward_smoke_report.{json,md}`；
- `label_validity_report.{json,md}`；
- 可用于 metric 的 sim-valid validation split，或明确标注只能做 `MVP_SMOKE/PILOT_ONLY`。

## 目标

选出真正给控制器使用的 risk score。重点不是让 future head 单独最高，而是选出最适合触发 early correction 的信号。

## 候选信号

1. `p_slip_current`；
2. `p_instability_H1/H3/H5`；
3. `p_slip_current * p_instability_H1`；
4. `p_slip_current * max(H1,H3,H5)`；
5. force threshold；
6. `Ft/(Fn+eps)` / q-style risk；
7. logistic/calibrated score，如样本量足够。

## 具体任务

1. 在 sim-valid validation split 上计算所有候选 score；
2. 对比 current-slip-only、future-only、force-only、gated scores；
3. 统计：
   - F1 / AUROC / AUPRC；
   - false alarm rate；
   - early recall；
   - mean/median lead time；
   - calibration/ECE；
4. 检查 raw future risk 是否在 stable/no-contact 上饱和；
5. 选出 deployment risk score；
6. 给出阈值和 fail-safe 策略。

## 产出文件

- `risk_calibration_report.json`
- `risk_calibration_report.md`
- calibration plots
- threshold table

## 通过条件

- 被选中的 risk score 必须和 current-slip-only、force-threshold baseline 对比；
- 若 future-risk 不带来收益，则只作为辅助诊断特征；
- 报告必须说明 false alarm 与 lead time 的 tradeoff；
- 控制器阈值必须写清楚。

## 最小实验规模

若要标为 `EVAL_READY`，建议：

- 至少 3 类 object/object family；
- 至少 3 个 friction bins；
- 至少 3 个 mass/lift acceleration regimes；
- 至少 3 个 seeds；
- 每个主要 controller condition 至少 20 trials。

不满足时标为 `MVP_SMOKE` 或 `PILOT_ONLY`。
