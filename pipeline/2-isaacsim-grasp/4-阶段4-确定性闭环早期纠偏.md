# 4 — 阶段4：确定性闭环早期纠偏

## 为什么 RL 之前必须做这个

如果确定性规则/MPC/CEM 都无法利用风险信号改善抓取，直接 RL 很可能只是学习仿真 artifact 或不稳定 reward。因此本阶段是 RL 的硬前置条件。

## 目标

证明 perception-control bridge 能在滑移发生前触发有效纠偏动作。

## 输入

- 阶段3选出的 deployment risk score；
- risk threshold；
- IsaacSim UR5/Robotiq/GSmini 或等价抓取场景；
- object/friction/mass/lift perturbation 配置。

## Controller 对比

至少包括：

1. no tactile baseline；
2. force-threshold controller；
3. current-slip-only controller；
4. selected/gated risk controller；
5. 可选 oracle upper bound。

## 动作集合

控制器可以选择：

- `hold`；
- `close_delta` / 增大目标夹持力；
- `open_delta` / 过力或失败时释放；
- `target_force_delta`；
- 可选 wrist/lift adjustment，但建议第一版先保持简单。

## 具体任务

1. 实现确定性控制器；
2. 跑 scripted perturbations：
   - friction；
   - mass；
   - contact offset；
   - lift acceleration；
3. 对比不同 controller；
4. 记录事件 timeline；
5. 统计 early warning / intervention 是否发生在 slip onset 之前；
6. 检查 over-force 和控制振荡。

## 每个 trial 必须记录

- `contact_start_t`
- `first_warning_t`
- `intervention_t`
- `slip_onset_t`
- `drop_t`
- `recovery_t`
- `trial_end_t`
- `max_force`
- `object_safe_force_limit`
- `no_drop_after_intervention`

## 产出文件

- `closed_loop_baseline_report.json`
- `closed_loop_baseline_report.md`
- event timeline plots
- controller comparison tables
- failure-mode table

## 通过条件

selected/gated risk controller 相比 no tactile、force threshold、current-slip-only，至少改善一个核心闭环指标：

- drop rate；
- slip event count；
- early intervention success；
- warning/intervention lead time；
- object displacement；
- over-force rate；
- action smoothness。

同时不能出现不可接受 over-force 或严重 action chatter。

## 完成后做什么

通过后可并行进入：

- `5a-阶段5-RL改进层.md`
- `5b-阶段6-实物小样本验证准备.md`

如果本阶段不通过，不要启动 RL，先回到阶段3或控制器设计。
