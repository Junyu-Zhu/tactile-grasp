# 1 — 阶段0：盘点与接口冻结（第一步先做）

## 为什么必须先做

这是整个 IsaacSim 闭环项目的地基。没有这个阶段，后续即使模型跑通，也很难判断：

- 用的是哪个 checkpoint；
- 输入预处理是否和训练一致；
- 输出字段是否能被控制器稳定消费；
- report 是否可复现；
- 后续指标是否可比较。

## 目标

冻结研究 claim、checkpoint、数据路径、输入输出 schema、artifact 目录和报告命名。

## 输入

需要确认：

1. Stage-I force/slip 模型 checkpoint；
2. Stage-II future-instability head checkpoint；
3. SPARSH encoder/backbone 配置；
4. 训练时的预处理：resize、frame stack、background subtraction、normalization、context stride；
5. IsaacSim tactile dataset 或 trial root；
6. artifact 输出目录；
7. 当前代码中可复用的 sim bridge / dataloader / evaluation script。

## 具体任务

1. 记录所有 checkpoint 的绝对路径和 hash/mtime；
2. 写清楚输入 tensor schema：`B, T, C, H, W` 或实际格式；
3. 写清楚输出 schema：
   - force vector；
   - `Fn/Ft/Fmag/Ft_over_Fn`；
   - `p_slip_current`；
   - `p_instability_H1/H3/H5`；
   - gated risk；
4. 规定每个 trial 的 metadata 字段：object、friction、mass、pose、contact state、gripper width、action；
5. 规定所有阶段报告输出到同一个 artifact root 下；
6. 在报告中明确：当前工作只支持“开始 IsaacSim 验证”，还不支持“闭环成功”主张。

## 产出文件

- `inventory_report.json`
- `inventory_report.md`

建议字段：

```json
{
  "status": "PASS_OR_BLOCKED",
  "stage_i_checkpoint": "...",
  "stage_ii_checkpoint": "...",
  "encoder_config": "...",
  "input_schema": "...",
  "output_schema": ["force", "p_slip_current", "p_instability_H1", "p_instability_H3", "p_instability_H5"],
  "artifact_root": "...",
  "known_blockers": []
}
```

## 通过条件

- 所有必需 checkpoint/config 路径存在；
- checkpoint 至少能 load，不要求 IsaacSim 运行；
- 输入/输出 schema 已写入报告；
- artifact root 已确定；
- 若缺文件，必须列为 blocker，不能默默跳过。
